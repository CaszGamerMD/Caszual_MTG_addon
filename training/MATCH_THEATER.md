# Commander Golem Match Theater

The Match Theater is a **read-only replay viewer with optional online artwork** for the standalone Commander rules diagnostic. It does not play Magic itself, implement additional rulings, or integrate with Minecraft.

## Omniscient hands and Scryfall card faces (2026-10-29)

New **diagnostic** match exports record `events[].spectatorHands`, containing
both players' actual hand card IDs and names at each recorded event. The
spectator viewer reveals both hands by default, with a **Hide hands** toggle.
This makes saved replays intentionally omniscient: do not share such exports
with people who should not see hands while a live game is being played.
Simulator `state()`, legal-action generation and AI policy observations
**still contain only hand counts**. The hand snapshots are recorded into the
replay event log separately; hidden library order is never exported. Old
replays cannot recover hands retroactively and still display face-down cards.

The viewer uses the [Scryfall card API](https://scryfall.com/docs/api) to
look up real printed card faces by exact card name. It caches each distinct
name for the lifetime of the page and requests **no faster than one lookup
per 600 ms** to respect Scryfall API limits. It displays actual card faces
for both hands, battlefield permanents, and public graveyard/exile galleries.
The card inspector shows larger artwork and a **Face 1 / Face 2** selector
for multi-faced cards. **Art: Off** disables online requests and reverts to
original CSS placeholders. This feature requires internet access to Scryfall:
it cannot display artwork offline, and unmatched custom tokens use the
placeholder. The viewer has no affiliation with Scryfall; images are from
Scryfall, not generated by this project.

## Spectator experience upgrades

- The **⇅ Seats** control swaps player positions while preserving both recorded hands.
- **Command zone** cards are displayed and inspectable whenever the replay marks a commander in that zone.
- Printed spells on the **stack** now show a face thumbnail; triggered abilities retain their accurate labels.
- **On camera** follows a card explicitly mentioned in commentary, without guessing any hidden information.
- **⚔ Combat ⟶** jumps to the next recorded combat moment, and failed Scryfall lookups expire after 45 seconds.
- Both the current 458-event spectator replay and the older 177-event sample use the upgraded viewer. Only the newer replay contains recorded hand identities.

## Open and watch a match

- **Open [the ready-to-watch 458-event spectator match](examples/budget-vs-goblins-spectator-20261029.html) or the [older sample](examples/match-theater-real-decks.html).** Download the HTML file using GitHub's file Download action and open it in Chrome or another modern browser. No server or installed software is needed; live Scryfall art needs internet.
- To watch your own matches, open [the reusable viewer](viewer.html) in a browser, select **Open replay**, and choose a simulator **turn-replay JSON**. You can also drag and drop the JSON file onto the page.
- Running a new simulation with \`python training/simulator.py simulate --demo\`, \`diagnose\`, or \`pool-diagnose\` exports fresh self-contained HTML from this template. New exported matches carry a public LIFO stack, priority, exile cards, and mana pools.
- Press **Play** or **Space** to advance automatically. Switch between 0.5×, 1×, 2×, and 4×; enable **Highlights** to skip low-interest log entries during automatic playback, or use arrows and the timeline to inspect every event.
- Select a permanent to see its public characteristics; select **Player 1 zones** or **Player 2 zones** for graveyards and exile. **Rules questions** remain separately editable and exportable for review.

## What you see

By default, the top half of the felt tabletop is Player 2 and the bottom half is Player 1; seats can be swapped. Each has separate creature, other-permanent, and land rows, plus a life wheel and a spectator hand row (face-down for older recordings). New cards glow as they appear; changes in counters or tapped status are outlined. When recorded in an event, attackers and blockers receive a combat highlight. Cards use original offline CSS frames and abstract symbols; card art is not invented or loaded remotely.

The center shows the active player, turn, phase, and current event. The right side shows the *actual recorded* public priority stack with its next-to-resolve item first, plus a searchable nearby play log. Each physical card can be inspected for public attributes. The omniscient spectator export intentionally shows both recorded hands, while legacy recordings display only hand counts and card backs. Library order remains hidden.

## Replay format and backward compatibility

- Viewer input remains \`schemaVersion: 1\` and \`kind: "turn-replay"\` or \`kind: "rules-review"\`.
- Raw \`events\` and older \`packedReplay: 1\` / \`compactEvents\` both work.
- The packed format keeps its original card-index and player-array slots, appending new **public** information rather than changing existing indexes.
- New compact event states include \`state.stack\`, \`state.priority\`, \`players[].exile\`, and \`players[].manaPool\`, with event-varying kind, creature status, loyalty, charge counters, attachment, hexproof, and ward characteristics.
- Older compact files genuinely lack some state fields. The viewer identifies the stack as **not recorded**, not empty or fabricated; old exile and mana records default to empty/unknown in display. Re-exporting from a new simulation produces richer state.
- Saved sample HTML contains a replay generated before stack capture was added. Its existing combat events and life history are authentic; its stack cannot be reconstructed retroactively.

## Safety and limits

The viewer intentionally has **no network dependencies** and uses text nodes to display replay/card names, not \`innerHTML\`. Generated replay HTML escapes script delimiters from card/deck text. Saved spectator hand identities are serialized in a separate replay-only field and never sent in AI observations. Library order and future decisions are never serialized to public replay state. Rules questions are review notes only, not proof that a card is supported.

This is still a **two-player diagnostic approximation**, not a complete Commander engine. Visual flourishes never substitute for simulator decisions. The viewer does not change the engine's scoring or training and is not an AI player.

Regression checks are in \`training/tests/test_match_theater.py\`. The JavaScript is syntax-checked when Node.js is available, and the self-contained sample is checked for valid, nonempty replay data.
